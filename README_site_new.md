# ПРО красоту

## Назначение
Локальный React-сайт премиального салона красоты «ПРО красоту» в Минске.

## Подтверждённые требования
- Город и адрес: Минск, улица Ежи Гедройца, 2.
- Аудитория: женщины, мужчины, семьи; премиум-сегмент.
- Обязательные блоки: услуги, мастера, цены, портфолио, отзывы, контакты, онлайн-запись.
- Стиль: luxury.
- Форма записи: нужна.
- Источники контента: Dikidi-профиль и страница услуг.
- Режим работы: локальная разработка, GitHub и production-публикация через Vercel.

## Технический план
- React + TypeScript.
- Локальная одностраничная презентационная страница.
- Адаптивная верстка для мобильных, планшетов и десктопов.
- Цены, услуги, мастера, отзывы и фотографии подключаются из проверенного контента Dikidi.

## GitHub workflow

- Каждая самостоятельная задача получает GitHub Issue.
- Для задачи создаётся отдельная ветка.
- Изменения проходят локальные проверки и code review.
- После проверки создаётся Pull Request в `main`.
- После согласования PR выполняются merge, push и production deployment.

## Ограничения
Для внешнего контента нужно фиксировать источник и дату последней проверки. Цены, список услуг, имена мастеров, отзывы и фотографии должны перепроверяться перед production-публикацией.

## Локальный запуск
```bash
npm install
npm run dev
```

Проверка production-сборки:
```bash
npm run build
```

## Переменные окружения

Создайте `.env` по шаблону `.env.example`. Реальный `.env` не коммитится.

```env
TELEGRAM_BOT_TOKEN=ваш_токен_бота
TELEGRAM_CHAT_ID=id_чата
```

Секреты используются только сервером и не должны попадать в клиентский код, Git или публичный bundle.

## Заявки в Telegram

Сервер отправляет заявки через Telegram Bot API. Скопируйте `.env.example` в `.env` и укажите токен бота и ID чата:

```bash
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...
```

Переменные нужны серверу `server.mjs` и не должны попадать в клиентский код или Git. Для проверки формы соберите проект командой `npm run build`, затем запустите `node server.mjs` и выполните реальную тестовую заявку.

## Production readiness

Перед публикацией проверьте build, environment variables, загрузку изображений, мобильную версию, форму заявки, API, отсутствие localhost-ссылок и статус deployment `READY`. После публикации укажите production URL, commit SHA и результат smoke-check.
